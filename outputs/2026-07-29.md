### 题目 1：LoRA 训练过程中，Transformer 的哪些参数被更新？全量 SFT 和 LoRA SFT 的 learning rate 设置有什么技巧和差异？

**来源依据：**
- 2026大厂大模型/Agent面试题_面试_SiYuanFeng-AtomGit开源社区 - https://gitcode.csdn.net/6a236d7b662f9a54cb7a2bf1.html - 面经或社媒 - 需进一步验证
- 大厂LLM应用岗上岸面经：面28家拿offer，拆解“必问考点+避坑指南”这篇把面试重点（RAG/Agent/微调是核心 - 掘金 - https://juejin.cn/post/7531039727782068274 - 技术博客 - 需进一步验证

**可信度：** 中（面经汇总，但属于高频考点，可辅助工程理解）

**考察点：** LoRA 原理、训练参数理解、SFT 工程配置

**面试口头版回答：**
“LoRA 微调时，预训练模型的原始权重（W0）是被冻结不更新的。我们只在 Transformer 每一层的自注意力模块中，对 Query、Key、Value 和 Output 这四个投影矩阵插入了低秩适配器（LoRA Adapter）。具体来说，对于每个被选中的权重矩阵，我们用两个小矩阵 A 和 B 的乘积（B * A）来表示更新量 Delta_W，训练时只更新 A 和 B。至于学习率，全量 SFT 因为要调整整个模型的所有参数，通常需要较小的学习率，比如 1e-5 到 5e-5 之间，以防破坏预训练特征。而 LoRA 因为是训练一个很小的增量，它允许我们使用更大的学习率，实践中我常用的范围是 1e-4 到 5e-4，差不多是全量 SFT 的 5-10 倍。这能帮助适配器更快收敛。”

**深入理解版回答：**
LoRA（Low-Rank Adaptation）的核心思想是冻结预训练模型的全部权重，并在模型前向传播过程中注入可训练的秩分解矩阵。在 Transformer 架构中，LoRA 默认并且最常用于修改 **自注意力（Self-Attention）** 模块中的四个投影矩阵：`W_Q`（Query）、`W_K`（Key）、`W_V`（Value）和 `W_O`（Output）。实际项目中，通常只对 `W_Q` 和 `W_V` 进行 LoRA，因为这两个矩阵对分布偏移更敏感，能更好地适应下游任务。

**工程细节一：更新哪些参数？**
- **冻结部分：** 所有原始的 Pre-trained weights（包括 Attention 的其余部分、整个 FFN 层、LayerNorm 等）和 Embedding 层均不参与计算图。
- **更新部分：** 只更新插入的 Adapter 矩阵 `A` 和 `B`。`A` 通常使用随机高斯初始化，`B` 初始化为 0，使得训练开始时 LoRA 模块的输出为 0，不影响模型输出。
- **推理时合并：** 训练结束后，可以将 `A` 和 `B` 的乘积加到原始权重上（`W_new = W0 + α * (B · A)`），然后丢掉 LoRA 权重，推理时完全不增加额外计算量。

**工程细节二：学习率设置的技巧与原因**
- **原理差异：** 全量 SFT 面对的是一个高维、复杂的损失景观。如果学习率过大，很容易导致模型灾难性遗忘（Catastrophic Forgetting），丢失预训练学到的通用语言能力。因此，全量 SFT 的学习率通常很低，且常配合使用学习率预热（Warm-up）和余弦退火（Cosine Decay）策略。
- **LoRA 的优势：** LoRA 是在预训练权重的邻域空间内进行学习，增量非常小。由于需要更新的参数数量级远小于全量 SFT，它可以使用更大的学习率来加速收敛，而不会大幅扰动原有特征。我实践中的经验是：在相同模型和数据集下，LoRA 的初始学习率可以设为全量 SFT 的 10 倍左右（例如 3e-4 vs 3e-5）。
- **注意事项：** LoRA 学习率也不宜过大，否则会导致适配器训练不稳定，出现 loss 震荡。通常建议在 1e-4 到 5e-4 之间，并配合 AdamW 优化器及 Weight Decay（通常设为 0.01）。

**常见追问与回答：**
- **追问 1：为什么通常只更新 Q 和 V，而不是所有层？**
  回答：因为 Attention 中的 Q 和 V 矩阵对于捕捉输入数据间的交互模式和上下文的数值分布变化更为敏感。更新 K 和 O 矩阵带来的收益在边际上会递减。同时，减少 Adaptor 数量能节省显存和训练时间，在不明显降低效果的前提下提升效率。
- **追问 2：LoRA 的秩 r 怎么选择？它在工程上如何影响模型效果？**
  回答：秩 r 决定了 LoRA 的表达能力。r 越小，可训练参数量越少，但可能欠拟合；r 越大，表达能力越强，但参数量线性增加。项目实践中，对于 7B 模型，r=8 或 r=16 是比较常见的折中选择。对于非常复杂的任务（如代码生成），可能需要 r=32 甚至 r=64。我们可以通过观察验证集 Loss 或下游任务指标（如 BLEU, ROUGE）对 r 进行调优。

**项目联系：**
在我们的项目中，我们使用 LoRA 微调一个 7B 的基座模型，使其适配特定的客服问答风格。我们只在注意力层的 Q 和 V 上插入了 LoRA，秩设为 8。关键经验是，我们将全量 SFT 的学习率（3e-5）直接用于 LoRA 训练，导致收敛非常慢且 loss 不降。后来参考一些实践，将学习率调整为 3e-4，并在前 10% 的训练步数进行预热，loss 迅速下降并在相同 epoch 内取得了更好的回答质量。

**记忆关键词：**
冻结预训练权重、Adapter 矩阵 (A,B)、注意力投影矩阵、学习率比值 (5x-10x)、显存节省、灾难性遗忘

### 题目 2：QLoRA 量化微调中，为什么选择 NF4 和 FP16 这组组合？NF4 的分布拟合逻辑是什么？

**来源依据：**
- 真实面经案例集锦 - AgentGuide - https://github.com/adongwanai/AgentGuide/blob/main/docs/04-interview/12-company-interview-cases.md - 面经或社媒 - 需进一步验证

**可信度：** 中（来自社区面经汇总，但属于 QLoRA 核心原理，与论文一致）

**考察点：** QLoRA 原理、量化理解、显存优化

**面试口头版回答：**
“QLoRA 使用 NF4（4-bit NormalFloat）和 FP16（16-bit 浮点）的组合，这是为了在极低比特量化下最大化模型精度。NF4 是 QLoRA 提出的一个关键创新，它是一种信息论上最优的 4-bit 数据类型，专门针对服从零中心正态分布的权重进行优化。NF4 的分布拟合逻辑是，预训练模型的权重分布近似于正态分布，而且有大量权重集中在 0 附近。普通均匀量化会把大量量化区间浪费在概率很低的尾部，而 NF4 通过计算分位数来划分不均匀的区间，使得每个区间包含的权重数量大致相同。这样，梯度噪声大的尾部被合并，而信息量大的‘0’附近区域得到更精细的表征。混合使用 FP16 作为计算精度，是因为 NF4 主要用于存储，为了在反向传播中计算梯度，必须先将 NF4 权重反量化回高精度的 FP16 进行计算，从而保证训练的数值稳定性。”

**深入理解版回答：**
QLoRA 的成功在于它通过新的量化方法，在不显著降低微调效果的前提下，将单张 24GB 显存的 GPU 能够微调的最大模型从 7B 提升到了 65B。其核心组件是 `NF4` 和 `Double Quantization`。

**1. 为什么选择 NF4 + FP16？**
- **NF4 (NormalFloat4)**：这是一种对零中心正态分布最优的 **数据类型的量化方法**。
    - **普通 4-bit 量化的局限**：传统的均匀量化（如 Int4）假设数据均匀分布。但 LLM 的权重近似正态分布，大部分值在 0 附近，小部分值在两端（粗尾）。均匀量化会导致靠近 0 的区域（最重要的区域）量化间隔过粗，而粗尾区域浪费了量化精度。
    - **NF4 的优势**：NF4 通过对正态分布的累积分布函数（CDF）进行分位数量化来解决这个问题。它首先估计前向传播中权重的绝对最大值，将权重归一化到 [-1, 1] 区间，然后找到能够将标准正态分布均匀划分为 16 个（2^4=16）等概率区间的 16 个分位点。这些分位点 **不均匀** 地分布在 [-1, 1] 区间上。靠近 0 的分位点密度高（精度高），远离 0 的密度低（精度低）。这就确保了在信息密度高的区域分配了最多的量化精度。
- **FP16 (16-bit 半精度浮点)**：NF4 只用于 **存储** 权重以节省显存。实际进行矩阵乘法计算时，需要将 NF4 反量化（Dequantize）回计算精度（通常是 FP16）。此外，为了进一步压缩显存，QLoRA 还对量化常数做了二次量化（Double Quantization），也使用 FP16 存储。

**2. 工程流程**
- **训练时**：预训练权重以 NF4 格式存储。Forward 时，NF4 权重被临时反量化回 FP16 进行计算；Backward 时，梯度通过 `torch.autograd` 自动传给反量化操作，计算 LoRA 适配器权重（A 和 B，这两项始终是 FP16 精度）的梯度。原始 NF4 权重不更新。
- **推理时**：可以将训练好的 LoRA Adapter 合并进原始 NF4 量化模型中，然后以 4-bit 模型运行；也可以将 LoRA 权重保留，加载时动态合并。

**常见追问与回答：**
- **追问 1：NF4 相比 Int4，在训练任务上能带来多大的精度提升？**
  回答：根据 QLoRA 原论文的评测，在多种任务（如 MMLU， GSM8K）上，NF4 量化后的模型在微调前后，其性能损失相对于 FP16 微调几乎可以忽略不计（通常在 1% 以内）。而普通 Int4 量化可能会带来 2-3% 甚至更多的性能下降。尤其是在对话和推理任务上，NF4 的优势更为明显。
- **追问 2：QLoRA 训练时，这个反量化操作如何影响显存和速度？**
  回答：反量化是逐块（如按每 64 个权重一块）进行的，存储 NF4 权重和 Double Quantization 常数总共只占原来 FP16 权重 1/4 左右的显存。虽然反量化引入了少量计算开销，但由于 QLoRA 避免了在 GPU 上存储大量的高精度权重，允许更大的 Batch Size 或训练更大的模型，整体吞吐（Throughput）通常是高于在相同显存约束下跑 FP16 全微调的。

**项目联系：**
我们的项目需要微调一个 70B 的模型，但单张 A100 80G 显存有限。我们通过使用 QLoRA 技术，成功将模型微调所需的显存从超过 140GB 降低到了大约 48GB，得以在两张 GPU 上完成。我们使用 NF4 量化基座模型，并配合 Paged Optimizer（QLoRA 的另一个创新）来分页处理偶发的梯度峰值。这个组合让我们能够在消费级硬件上复现一定的 SFT 效果。

**记忆关键词：**
NF4、分位数量化、Double Quantization、反量化（Dequantize）、精度与存储平衡、显存瓶颈

### 题目 3：SFT 微调时，训练数据是怎么构造的？如何保证样本多样性和质量，防止过拟合？

**来源依据：**
- 2026大厂大模型/Agent面试题_面试_SiYuanFeng-AtomGit开源社区 - https://gitcode.csdn.net/6a236d7b662f9a54cb7a2bf1.html - 面经或社媒 - 需进一步验证
- 大厂LLM应用岗上岸面经：面28家拿offer，拆解“必问考点+避坑指南”这篇把面试重点（RAG/Agent/微调是核心 - 掘金 - https://juejin.cn/post/7531039727782068274 - 技术博客 - 需进一步验证

**可信度：** 中（高频考点，面经常见且实践性强）

**考察点：** 数据工程、微调配置、过拟合应对

**面试口头版回答：**
“数据构造是 SFT 的核心。我的做法分三步。第一步，**数据来源与清洗**，主要从历史对话日志、人工标注的问答对、或者使用更强的模型（如 GPT-4）对现有文档进行蒸馏生成。第二步，**模板化与格式化**，将所有样本统一转为指令-输入-输出的格式，并使用 ChatML 或 Alpaca 风格模板，保证模型看到一致的格式。第三步，**质量与多样性保证**。质量上，我们会让标注人员对指令的清晰度、答案的正确性和全面性打分，去除低分数据。多样性上，我关注任务类型（如推理、摘要、代码）的均衡，并通过 Embedding 聚类去除语义高度相似的样本。为了防止过拟合，我一般保持数据量在 1000-5000 条，并且训练时使用较少的 Epoch（1-3 轮），同时监控验证集 Loss。如果验证集 Loss 在某个点突然上升，就立即 Early Stopping。”

**深入理解版回答：**
SFT 数据构造不仅是一个技术活，更是一种对模型场景理解深度的一种体现，处理不好很容易导致过拟合或灾难性遗忘。

**1. 数据构造 Pipeline**
- **来源**：最理想的是面向业务的真实对话数据（日志清洗），其次是人工标注。如果都没有，可以退而求其次使用 LLM 蒸馏（Self-Instruct）。`清洗`阶段需要去除包含 PII（个人身份信息），政治敏感，以及答非所问的 Bad Case。
- **模板构建**：使用统一的 Prompt Template （如 `[INST] {instruction} [/INST] {response}`）。这个模板必须在 `训练` 和 `推理` 时保持一致。`Input` 字段有时为空。很多实践表明，在 Loss 计算时，只计算 `Response` 部分的 Loss，忽略 `Instruction` 部分的 Loss，能提升模型的对话能力。

**2. 保证质量与多样性**
- **质量过滤**：不能只用数量堆。使用 `LLM as a Judge` 方法，让一个评分模型对每个训练样本的`有帮助性(Helpfulness)`, `准确性(Factually Correct)`, `安全性(Harmlessness)`进行打分，筛掉低分样本。
- **多样性保证**：过拟合的一个核心原因是数据单调。保证多元性的几个方法：
  1. **任务分类平衡**：确保数据集中包含不同领域的指令，例如推理、创意生成、信息提取、上下文理解等。
  2. **语义去重**：对所有样本的 `Instruction` 进行 Embedding，计算两两相似度，删除相似度超过阈值（如 0.9）的样本。
  3. **控制指令格式**：不要让模型的对话模版“人格”固化。刻意混入不同措辞的指令（如 ‘总结一下’、‘用一句话概括’、‘你能告诉我这段话的核心是什么吗？’）可以提高 LLM 的泛化能力。

**3. 过拟合的工程应对**
- **验证集**：必须划分验证集（约 10-20%），并在训练时监控 `Validation Loss` 和 `Perplexity`。
- **正则化**：LoRA 本身就带有隐式的正则化效果（限制了参数量）。此外可以增加 `Weight Decay`（0.1 左右）。
- **Early Stopping**：当验证集指标连续 N 步不提升时停止训练，防止模型记忆噪声。
- **学习率**：使用余弦退火（Cosine Decay）和 Warm Up。
- **Dropout**：在 LoRA 的 `A` 或 `B` 矩阵中适当添加较小的 `Dropout Rate`（如 0.1），可以进一步提升泛化能力。

**常见追问与回答：**
- **追问 1：训练数据中 Instruction 部分的 Loss 你是怎么处理的？**
  回答： 通常我们直接计算整个序列的 Loss 是不合适的。我们采用 `Masking` 的方式，在计算 Loss 时，只对 `Response` 部分进行梯度回传，`Instruction` 部分的 Loss 被 Maked 掉（设为 0）。这样做可以让模型更专注于学习如何组织输出，不被指令格式干扰。
- **追问 2：你如何判断数据量是否够？数据质量高但量少，和低质海量数据你怎么选？**
  回答： 对于通用能力泛化，我倾向于“量小质精”。1000 条高质量、多样的、精心模板化的数据，其微调效果通常优于 10 万条带有噪声、缺乏多样性的数据。在资源有限时，我应该先花精力优化数据的 `Diversity` 和 `Quality`，而不是盲目增加数据量。

**项目联系：**
在项目中，为了微调客服 Agent，我们初期从生产日志中捞取了 20000 条对话，发现 Loss 降不下去。排查后确认是因为很多用户的“问句”本身就很模糊或存在错别字。我们引入了一个质量过滤流程：先用一个专门判断“问题清晰度”的规则过滤掉低质量问句，再用 Embedding 聚类去重，最终获得了 3000 条高质量的（清晰问题 + 正确回复）训练对。微调后的模型在回答精确度上直接提升了 15%，且泛化性良好。

**记忆关键词：**
数据清洗、任务分类平衡、Embedding 去重、Mask Loss、Early Stopping、过拟合

**1. 你的项目中，RAG 系统的效果是怎么量化的？你用的具体指标是什么？**
面试口头版：我们主要从三个维度量化 RAG 系统效果：一是 **检索质量**，用 `Recall@k` 和 `MRR（平均倒数排名）` 来衡量召回的准确性；二是 **生成质量**，用 `Faithfulness（忠实度）` 评估模型是否遵循了检索到的上下文，以及 `Answer Relevancy` 判断回答是否与问题相关；三是 **端到端效果**，我们会针对 200 个业务 Case 进行人工打分，对比上线前后的用户满意度。我们使用框架如 RAGAS 来自动化计算这些指标，这样每次修改了 Chunk 策略或 Reranker，都能立刻看到指标变化，方便迭代。

**2. 你如何处理 LlamaIndex 和 LangChain 在 RAG 项目中的角色分工？**
面试口头版：我们通常将 LlamaIndex 和 LangChain 混用。LlamaIndex 提供非常强大的数据索引和检索能力，比如 `Document`、`Index`、`VectorStoreIndex` 以及复杂的 `QueryEngine`，在构建知识库和做高效检索时非常好用。角色上，LlamaIndex 充当“数据管理 + 检索工程师”。而 LangChain 更擅长编排 Agent 流程、定义 Tool 以及处理多轮对话中的 Memory 和 Prompt 模板。所以我们让 LlamaIndex 负责将文档高效地转储到向量库并提供出色的检索接口，然后将这个接口作为一个 `Tool` 暴露给 LangChain 的 Agent。LangChain 作为“调度员”，负责决策何时去调用该工具，并处理返回的上下文来生成最终回复。

**2. SFT 和 RLHF 的作用有什么区别？RLHF 的基本流程是什么？**
面试口头版：SFT 主要作用是教模型学会“遵循指令并模仿特定的回复风格”，用的是监督学习；而 RLHF 的主要作用是“对齐”，它让模型的输出更符合人类的偏好（如更有帮助、更无害）。虽然 SFT 也会提升回复质量，但对于更复杂的“价值观对齐”和“避免有害内容”上，RLHF 更有效。RLHF 流程分三步：第一步，用人类偏好对（不同模型回复的比较）训练一个 Reward Model（奖励模型）；第二步，用 SFT 好的模型作为 Policy Model；第三步，Policy Model 生成回复后，Reward Model 给回复打分，PPO 算法用这个分数去更新 Policy Model，让它学会输出高分的回答。

## 3. 今日必背问答卡片

### 卡片 1
- **Q：** LoRA 微调为什么能节省显存？（从参数量和梯度存储角度解释）
- **A：** 因为 LoRA 只更新插入的 A 和 B 矩阵，原始模型权重全部冻结。优化器需要维护的状态（如 Adam 的一阶、二阶动量）只和 LoRA 参数有关，数量级比全量 SFT 小几个数量级。另外，中间激活值（Activations）也只计算 LoRA 分支，相比全模型的反向传播，显存占用大幅减少。
- **一句话记忆法：** LoRA 只训练“小补丁”，不训练“整件衣服”，所以省显存。
- **复习标签：** #LoRA #SFT #微调优化 #显存

### 卡片 2
- **Q：** QLoRA 的 Q 指什么？它是如何实现用单卡 24GB 显存微调 65B 模型的？
- **A：** Q 指 Quantization（量化）。它通过 NF4 将基座大模型权重量化到 4-bit（减少约 4 倍存储），同时使用 Double Quantization（双重量化）进一步压缩量化常数占用的显存，还引入了 Paged Optimizer（分页优化器）处理偶尔的显存尖峰。这使得大模型“体重”大幅降低，能塞进小显存里训练。
- **一句话记忆法：** QLoRA 是给模型“压缩装袋”，小背包也能抗大模型。
- **复习标签：** #QLoRA #量化 #NF4 #显存优化

### 卡片 3
- **Q：** SFT 微调时，为什么要关注 “Instruction Loss Masked”？它有什么好处？
- **A：** “Instruction Loss Masked” 意味着在计算损失时，只计算 `Response` 部分的 Loss，而把 `Instruction` 或 `Input` 部分的 Loss 掩盖掉（设为 0）。好处是能让模型更专注于学习如何根据指令组织高质量的回复，而不是把心力花在“背诵”指令模板上，可以提升模型在对话任务中的泛化性。
- **一句话记忆法：** 只给回复打分，不给题目打分，模型才会专心学答题。
- **复习标签：** #SFT #微调 #数据构造 #LossMask

### 卡片 4
- **Q：** LoRA 的 Adapter 在部署时，可以采用哪两种方式？各有什么优缺点？
- **A：** 一种是 **合并推理**（Merge & Deploy），将训练好的 `B * A` 乘上 scale 后与原始权重相加，输出新权重，部署时无额外延迟。另一种是 **分离部署**（Separate & Deploy），在推理框架（如 vLLM）中支持动态加载多个 LoRA Adapter。分离部署可以实现多租户，一个基座模型服务于不同任务。合并推理更快但灵活性差，分离部署有微小延迟但方便管理和热更新。
- **一句话记忆法：** 合体（合并）跑得快，分身（分离）换得勤。
- **复习标签：** #LoRA #模型部署 #Adapter #vLLM

### 卡片 5
- **Q：** 你如何判断你的 SFT 模型是否过拟合了？
- **A：** 通过观察 **训练 Loss** 和 **验证集 Loss**。如果训练 Loss 持续下降趋向于 0，但验证集 Loss 先下降后开始平稳甚至回升（即 Loss 曲线呈 V 型或 U 型），说明模型开始记忆训练数据的噪声，出现了过拟合。同时，手动检查模型在验证集上的回复，会发现模型背答案痕迹重，对新问题的泛化能力变差。
- **一句话记忆法：** 训练成绩一直在涨，但“模拟考”成绩变差了，就是学“死”了。
- **复习标签：** #SFT #过拟合 #模型评估 #验证Loss

## 4. 今日面试专项训练

### 4.1 大模型理论追问题

**问题：**
在 SFT 中，训练数据的配比（数据来源、任务类型比例）如何影响 LoRA 微调的表现？你如何避免微调后的模型在通用能力上退化（Catastrophic Forgetting）？

**面试口头版参考答案：**
数据的配比直接影响模型学会的能力。如果太多翻译数据，模型回答会泛化出“翻译腔”；全是数学题，它对话能力会变差。我通常会控制一个比例，比如以 60% 的垂直领域数据（客服 QA）为主，混入 15% 的通用对话、15% 的推理和 10% 的翻译任务，确保它能力不失衡。防止 Catastrophic Forgetting 最有效的方法是：1. **尽量使用 LoRA**，因为它本身只学习增量，对基座权重扰动小；2. 在训练数据中混入 5%-10% 的通用预训练语料，类似“复习”机制；3. **限制学习率**，在 LoRA 中不应用过高的学习率；4. 定期做 **Early Stopping**，并在验证集上评估模型的通用能力（如用公开的 C-Eval 子集）。

**深入理解版参考答案：**
- **问题本质：** 当模型在特定领域数据上过多训练时，其内部表示会向该领域“偏移”，导致泛化能力下降。微调相当于一个“局部最优”搜索，如果只盯着客服数据，模型可能会“忘了”如何做创意写作。
- **数据配比的重要性（多任务学习视角）：** 将不同任务的数据混合训练，可以看作是隐式的 Multi-Task Learning。这不仅让模型学到“如何在客服场景说话”，也迫使模型保持对其它不同格式指令的响应能力。否则，模型会陷入“模式崩塌（Mode Collapse）”。
- **工程策略：**
  1. **重放（Replay）/ 复习**：在 SFT 数据中加入一定比例的、高质量的开源通用 SFT 数据（如 Alpaca, ShareGPT），通过“复习”来维持通用问答能力。
  2. **数据加权（Data Weighting）**：对不同任务的数据赋予不同的采样权重。对于不想丢失的通用能力，可以降低其混合比例，但放在训练集最后几个 Epoch，让模型“温习”一下。
  3. **知识蒸馏**：在训练 LoRA Adaptor 时，同时使用 KL 散度损失，让 Adaptor 的输出分布尽量接近原始 Pre-trained 模型的输出分布，防止大幅偏离。
- **实验迭代**：这是一个“调配方”的过程。没有绝对正确的比例，通常需要在垂直任务和通用任务各自的小评测集上持续验证，通过调整比例来找到平衡点。在实践中，LoRA 由于其低秩性质，相比于全量微调天然的更能缓解遗忘，所以也是个很好的默认选择。

**可能追问与回答：**
- **追问 1：你如何定义“通用能力退化”？如何设计一个简单的评测集来量化它？**
  回答：我构造一个定性的“通用能力”评测集，包含 100 条不相关领域的题目：比如写一封邮件、做一个简单的总结、猜谜、常识问答（如“为什么天是蓝的？”）。微调后，用模型回答去人工打分（1-5 分），对比微调前后的平均分，如果出现明显下降（如 20% 以上），就定义发生了退化。
- **追问 2：当 Recalling 发生时，放在训练数据里的“通用数据”和“新领域数据”是按什么策略进行混排的？**
  回答：通常我不是简单的 1:9 混排。我倾向于 **学习率余弦退火 + 课程学习**。在训练初期（Warm-up 阶段），使用较高的新领域数据比例，让模型快速学习新能力；在训练后期的余弦退火阶段，逐渐增加通用数据的比例，让模型在学习率较低时慢慢“回忆”起旧的分布，这个过程更像一个平滑的迁移。这可以最大程度吸引新能力而软化对旧分布的冲击。
